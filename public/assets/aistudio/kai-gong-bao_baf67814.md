## 怎么用这份开工包

1. 第一次开工，先把「项目简介」「范围冻结」「风格圣经」「工具分工与工作纪律」四节整段发给 dsh，让它复述一遍项目是什么、不能做什么。复述对了，再发任务。
2. 之后每次只发一个任务：从「任务拆分与验收」里按顺序取，或直接复制「第一个任务投喂文本」。
3. 每个任务做完，先在 Godot 里实际运行，按该任务的验收清单逐项打勾。全过才提交 Git，才发下一个任务。
4. Agent 提出要加手册和开工包里没有的东西（新敌人、新颜色、新系统、新场景元素），一律先拒绝，记到「未决清单」，等人工确认。
5. Agent 卡住超过两轮（同一个问题改两次还不对），不要让它继续硬改。把出错的代码和报错原文发给 Qoder + Qwen3.8 Flash 复查，拿到第二意见再动手。
6. 每个任务验收通过后，Agent 按下面「送审包」一节生成一份送审包，交给人工发给 Muse 审核。Muse 通过后才开下一个任务。

## 送审包（每个任务做完生成，不提交）

送审包是给 Muse 审核用的临时材料，**不许提交进 Git 仓库**。生成在本地 `review/<任务号>/` 目录下，该目录已写进 `.gitignore`，提交时不会带上。

每个任务的送审包只含三样：

1. 实机截图一张 + 约 10 秒实机录屏一段（Godot 里实际跑起来的画面，不要只截编辑器）。
2. 验收清单逐项打勾的结果：每项写通过 / 不通过 + 实际看到的现象，不要只写“已完成”。
3. 运行日志 / 报错原文（有报错才贴，没有就写“无报错”）。

不用再贴改了哪些文件、改动摘要：代码和改动 Muse 直接去 GitHub 仓库里读。截图、录屏、日志发在聊天里就行，不要放进仓库——视频文件大，提交进仓库会让仓库越来越臃肿，克隆也变慢。

命名补充（2026-11-06）：一个任务如果有多张取证图，允许按内容命名（如 `screenshot_rules.png`、`screenshot_blackout.png`、`squint_human.png`），不必硬凑一张叫 `screenshot.png`；但报告里必须逐张写清它证明的是哪一条验收项。另外长跑日志除了 `EXIT=0 WALL=311`，还要带上游戏内的 print 流水（升级、破规、翻转各一行），否则只能证明「进程没崩」，证明不了「这 5 分钟里玩法真的发生过」。

取证方式补充（2026-11-06）：允许在 `review/` 下写 devtest 场景（`project/review/*.gd` + `.tscn`，`review/` 已 gitignore），用无头 Godot 直接跑，输出 `TEST [PASS]/[FAIL]` 断言与 `SCRIPT ERROR` 计数。当一个任务的行为只在特定时间点出现（例如 Boss 在第 20 分钟才登场，10 秒录屏只能拍到等待期），用 devtest 断言 + 定点截图代替录屏，并在送审包里逐张写清证明的是哪一条验收项。另外每改一次 `.tscn` 就要跑一次 `--headless --import` 解析检查：节点路径改了而脚本没同步，会让整个脚本加载失败，实机必崩（任务 13 踩过一次）。

送审包模板（Agent 每任务照此生成）：

```text
任务：任务 N（任务名）
提交：Git 提交号 / 分支名
1. 截图：review/N/screenshot.png
2. 录屏：review/N/gameplay.mp4（约 10 秒）
3. 验收清单：
   - [ ] / [x] 验收项 1：实际结果……
   - [ ] / [x] 验收项 2：实际结果……
4. 运行日志：无报错 / 报错原文……
```

## 项目简介（给 Agent 的一页纸）

做一款 2D 像素游戏，品类是类 Vampire Survivors 的幸存者类，题材是中式志怪 / 民俗恐怖。

第一眼身份按这个顺序，不许反：先是 2D 细腻像素画面，再是移动走位 + 自动攻击的幸存者类玩法，最后是中式志怪题材。规则、变脸、双世界是玩法系统，不是题材，不要把游戏做成规则解谜或恐怖冒险。

核心循环：移动走位 + 自动攻击 → 击杀掉经验 → 升级三选一 → 活过 20 分钟打 Boss → 结算 → 局外成长 → 再开一局。

三个玩法系统叠在核心循环上：

- 规则：每局从 9 条规则池里随机抽 3 条，破一条就刷出惩罚者，并失去本局干净通关奖励。
- 双世界 + 变脸（是一件事）：同一张夜墓地地图，人间与诡界共用同一布局、同一套色板，只换光圈、明度、刷怪表和拾取表。翻世界的那一刻就是变脸——人间是提灯少年，翻到诡界变脸成生旦形象。
- 双身份：人间提灯少年用灯焰攻击，稳、守；诡界生旦有两张脸，生是净面快剑（单体快攻），旦是骨白水袖（回旋范围），两张脸只在诡界内切换。翻回人间立刻变回提灯少年。

最终目标写死：成品的人间画面要和水墨夜 Demo 图逐项对上——同一座满月夜墓地、同一个提灯少年、同一群幽魂和僵尸、同一套羊皮纸 UI。诡界是同一张图翻过去的一面。

开发分两阶段：先做最简版完整 Demo，验证成立后才加丰富内容。现在只做第一阶段。

## 范围冻结

第一阶段 Demo 只做这些，多一件都不做：

- 1 张地图：夜墓地，人间 / 诡界共用布局与色板，翻世界有 3 秒冷却。
- 2 个世界身份：人间提灯少年；诡界生旦（生、旦两张脸）。
- 规则池 9 条，每局抽 3 条；切片阶段先写死 3 条，不做随机。
- 10 个升级，三类混池，升级时暂停弹三选一。
  - 落地口径（2026-11-06，长跑实测）：10 项合计只有 32 级，等级超过 32 之后三选一
    就没有任何可选项，面板空着而树已被暂停 = 整局永久卡死。所以 `upgrades.json` 另设
    `fallback` 一节「灯焰余烬」（人间灯焰伤害 +1，可重复），只在 10 项全满级时作为
    唯一可选项出现，不属于 10 项设计升级。
- 敌人 2 种：幽魂、僵尸；精英 2 型：红眼大幽魂、红眼印章僵尸。
- 第 20 分钟 Boss：机制已定（血量过半时改掉一条规则，并强行翻转一次世界、连带换身份），造型未定，先用放大版精英僵尸占位。
  - 落地口径（任务 13，2026-11-06）：占位不是把 64 档位图拉伸，而是按 96 档重新栅格化一份（风格圣经禁止小图放大当角色用）；Boss 战期间规则 8「天亮之前不要走断石墙后面」自动失效；每 5 分钟的精英轮换在 Boss 战期间暂停（数据开关 `enemies.json` 的 `boss.pause_elite_while_alive`，默认停）；换掉的规则从池里没在用的其它规则里抽，本局已破过的记录不撤销。
- 标题界面、结算界面、存档、局外成长最小版。
  - 落地口径（任务 14，2026-11-06）：存档在 `user://save.json`，只存局外货币、局外成长等级、设置三样；局外成长的条目、效果幅度、价格、每局产币速率开工包未定，全部是占位值，集中在 `data/meta.json`，改表不用改代码。
- 首发 Windows / Steam，简体中文 + 英文。

明确不做（Agent 提出来也要拒绝）：

- 第二张地图、联机、剧情系统、理智系统、第四张脸、规则池扩容。
- Demo 图上没有的场景元素：戏台、祠堂、纸扎铺、河边、农舍、红灯笼街道，一律不加。
- 第三种敌人、惩罚者的正式造型、Boss 的正式造型：未确认前只用占位，不许自行设计。
- 任何色板外的新颜色（见风格圣经）。

已作废方案（不是备选，看到代码、文档或素材里残留要清掉，也不许从旧稿里翻出来重做）：

- 朱红纸影、年画门神、戏班学徒主角、无面新娘、无面村神、纸神。
- 规则 2 的旧写法「必须站在自己灯笼的光里」与切片简化版「灯笼圈外停留不超过 5 秒」——已换成熄灯版，见规则表。
- 诡界难度的「密度 ×1.6、移速 ×1.15」——已换成「间隔减半」。
- 经验公式起始值 5——已调到 7。

## 风格圣经

风格唯一标准是水墨夜 Demo 图。图上有的照图锁死，图上没有的不许补。Agent 生成代码里的占位图、临时 UI、调试画面，也要遵守下面的色板和禁区，不许随手用 Godot 默认蓝、纯红、纯绿糊弄过去之后忘了换。

### Demo 图逐项清单（人间帧验收时逐项对）

- 俯视角夜墓地，顶部中央一轮满月，雾气弥漫。
- 正中是矮小的提灯少年：灰蓝长袍、黑帽、右手提暖橙纸灯笼。
- 灯笼光圈是全画面唯一的暖光源，也是玩家找自己的锚点。
- 幽魂：白灰飘带状，黑椭圆眼和口，大小不一。
- 僵尸：深灰长袍、黑帽、额头黄色符纸、双臂前伸。
- 精英只有两型：红眼大幽魂；红眼僵尸 + 胸前红色圆形印章 + 破烂袍。
- 场景只许十类元素：满月、墓碑（带汉字）、断石墙、竹子、草丛、土路石块、雾、绿色经验宝石，另加 2026-11-06 任务 5 拍板的两类冷色常亮光区载体——坟头鬼火、墓旁长明灯。除这些以外一律不加。
- UI 是羊皮纸框：左上 HP / LV / TIME，右上 COINS / EXP。锁框的样子和位置，数值只是示例。
- 诡界帧：同一座墓地、同一粒度、同一色板，只收紧光圈、加重雾、换刷怪表，人物变脸成生旦。
- 压暗口径（2026-11-06 拍板）：照 Demo 图走**全场景可读**——灯笼光圈是一团暖光池，光外仍要看得清墓碑、判定区、走近的怪，只是被压暗；不是「光外全黑、只有圈内可见」那一圈遮罩。人间 `dark_alpha` 0.65、诡界 0.72，人间雾 0.15。

### 像素粒度（细腻，不是粗颗粒）

- 主角与 Boss 精灵 96 × 96，普通敌人与精英 64 × 64，全游戏不混档。
- 地表瓦片 32 × 32 只是拼接单元，不许把小图放大当角色用；要当道具或判定载体用（例如大墓碑），必须另出 64 档精灵，不拿 32 瓦片 scale 两倍顶上去。
- 颗粒细、水墨边缘有 2–3 级近色过渡、选择性细描边（外轮廓 1 像素深色线，内部用近色分色），不套统一粗黑边。
- 脸和衣纹要能看清。走路 6–8 帧，受击 1–2 帧，死亡消散 3–4 帧；变脸用 3 个关键姿势加过渡帧。
- 省工只能减内容，不许降粒度。验收加两项：眯眼测试（眯眼还能分清玩家、精英、经验宝石）和放大 200% 看粒度。

### 锁定色板：18 色 + 经验绿

全游戏只许用这 18 色，另加经验绿一组（只给经验宝石）。第 19 色不存在。外部图片、AI 生图的颜色进游戏前逐色归到最近的一级，归不进去就改画，不许新增。

| 色族 | 深 | 主 | 浅 |
| --- | --- | --- | --- |
| 墨色系（约 55%） | 深墨 #06090B | 墨夜黑 #0E1418 | 墨蓝灰 #1C2A30 |
| 灰墨系（约 20%） | 暗灰墨 #3D4A48 | 灰墨 #5C6B6B | 浅灰墨 #8A9A94 |
| 灰绿系（约 10%） | 暗灰绿 #49554F | 僵尸灰绿 #6E7F74 | 浅灰绿 #93A894 |
| 骨白系（约 8%） | 骨白暗 #B9B09A | 骨白 #EDE6D6 | 骨白亮 #FAF6EA |
| 暖黄系（约 5%） | 暗琥珀 #B97F22 | 灯笼暖黄 #E8B34A | 灯芯亮 #F5D98A |
| 朱红系（≤2%，硬上限 5%） | 暗朱红 #7C1E10 | 朱红 #C8402A | 朱红亮 #E4654A |

经验绿（功能色，只给地面经验宝石，画面占比 <1%，色值为近似值、以 Demo 图为准）：经验绿 #57B96A、经验绿亮 #8FD694、经验绿暗 #3D8A4E。不要和灰绿系混用，草丛也不许用经验绿。

色板用法五条，写进任何美术和 UI 任务里：

1. 一盏灯原则：**暖光源**只有少年右手纸灯笼一种，诡界生旦手提的也是同一盏灯的换位。场景里不许出现第二盏**暖**灯；满月只是冷白圆盘，不发暖光。2026-11-06 拍板补充：允许坟头鬼火、墓旁长明灯、月光三处**冷色**常亮光区（用灰墨 / 灰绿 / 骨白系，禁暖黄、禁朱红、禁经验绿），强度压到 0.05–0.10，必须做得暗、冷、小，灯笼仍是全场最亮最暖的那个；它们的边界环常态不显示，只在熄灯判定那 5 秒亮出来。
2. 朱红配给制：只给精英的红眼和精英僵尸胸前的红色圆形印章。普通敌人、场景、UI、少年身上都不许有红；生旦妆面同样不用朱红。一帧朱红超过 5% 先删装饰和特效。
3. 渐变只许族内走：阴影往本族深一级压，高光往本族浅一级提，不许跨族借色。
4. 双世界只动参数不换色板：诡界收紧光圈、加重雾、墨色占比上调，色板一个颜色都不换；生旦也只用这 18 色（妆面骨白系 + 墨色系，衣纹墨色 / 灰墨 / 灰绿三系）。
5. 人间不许串味：生旦、水袖、脸谱只许出现在诡界帧，人间帧出现即重画。

### 美术素材分工（Agent 必须知道的边界）

- AI 生图（包括 Muse）只出概念、参考、单张立绘、场景参考和 UI 草稿，不直接当游戏素材出货。它出不了真透明底、精确 96 × 96 像素格和几十帧完全一致的精灵表。
- 正式精灵在 Aseprite 里照着参考图重画、修帧、切表，只用上面 18 色的调色板文件。
- 第三条路（2026-11-06 人工确认新增）：**程序化生成 Pixelorama 工程文件**。`tools/spritegen/` 用代码直接写 `.pxo`（真 RGBA 透明、精确 96/64/32 档、索引色锁死 18 色、多帧逐像素一致），产物同时给 `.pxo`（可编辑源）和 `.png`（Godot 读的那份）。这条不是取代 Aseprite，而是先把「规格」锁死：`.pxo` 用 Pixelorama 打开就能继续手改，改完用自带 CLI 回导 PNG：`Pixelorama.exe --quit -- --spritesheet -o out.png in.pxo`（注意 `--headless` 会段错误，索引模式依赖 shader，必须带窗口跑）。出货前一律过 `tools/spritegen/validate_sprite.py` 的 6 条门禁。
- 已否决：`godot_pixelorama_importer` 插件。它只解析 Pixelorama 1.0 之前的单流格式（ZSTD + 首行 JSON + 顺序 buffer），读不了现在的 ZIP 容器，仓库最后提交停在 2024-02-17。
- 动效分两类：逐帧动画（走路、攻击、变脸、死亡消散）用精灵表；灯笼闪烁、幽魂漂浮、雾、粒子用 Godot 代码做。AI 视频不进游戏当动画。
- 切片阶段全部用占位图（色块 + 文字标注即可），不做正式美术。占位图也要分清身份：人间灰蓝袍、诡界骨白妆面，不许只换数值不换样子。
